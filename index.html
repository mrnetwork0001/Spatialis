Natural speech

It’s a slot filler, not a grammar

Real speech is “uh, put a like, dark wood coffee table over there”. The parser scans the whole sentence for a verb, a noun, a finish, a colour and a placement, then acts on whatever it found — no fixed phrasing required.

“Spawn a Scandinavian lounge chair by the wall”
chairfloor · by wallscandinavian
“Add a floating marble coffee table”
coffeeTablecarrara marblefloat
“Give me a navy velvet sofa”
sofavelvetnavy
“Put a table lamp on the table”
tableLamptable
“Make the sofa leather”
restylesofatan leather
“Make it twice as big”
scale×2.0
“By the wall” is not “on the wall.” A chair asked for by the wall still stands on the floor — backed up to a wall and turned to face the room. Read as a wall mount, it would hang a chair at head height. That distinction is a separate anchoring path, and a test.
The pipeline

What happens between speaking and seeing

Four subsystems, each doing one job, talking through a shared registry rather than holding references to each other.

01 · HEAR

Voice intent

The ASR module transcribes. Interim text is shown, only the final acted on — and duplicates are debounced, because ASR emits them.

02 · PLACE

Surface anchor

World Query rays hit the room mesh. Height above the running floor estimate is what separates a table from the floor.

03 · DRESS

PBR materials

Each object gets a private material clone, then cross-fades colour, metalness and roughness together.

04 · ADJUST

Hand gestures

Pinch to drag, two hands to scale and rotate. Release hands it back to the anchor engine to settle.

Under the hood

Four subsystems

~3,065 lines of TypeScript, type-checked under strict, with 2,697 lines of tests behind them.

🎙

Voice Intent Engine

Scripts/VoiceCommandController.ts

Turns a spoken sentence into an intent, then drives the other three.

  • Longest-alias matching — “coffee table” beats “table”
  • Precedence rules — “add a big sofa” spawns, doesn’t resize
  • Spawn, restyle, recolour, scale, delete, clear
  • Plurals, disfluency and bare nouns all resolve
📐

Surface Anchor Engine

Scripts/SurfaceAnchorEngine.ts

Finds real surfaces and seats furniture flush against them.

  • Floor estimate eases toward new lows — one bad depth sample can’t drop the floor
  • Re-probes when the gaze hits the wrong surface type
  • Golden-angle spiral to clear existing furniture
  • Wall-adjacent placement via two chained probes
🎨

PBR Material Swapper

Scripts/PBRMaterialSwapper.ts

11 finishes and 10 tints, applied without touching anything else.

  • Per-object material clones — else one command repaints every sofa in the room
  • Every uniform write guarded for custom shaders
  • Tints preserve the finish: navy velvet stays velvet
✋

Hand Gesture Controller

Scripts/SpatialGestureController.ts

SIK hand tracking for pinch, drag, rotate and two-hand scale.

  • Thresholds scale to your hand — 3cm is a firm pinch on a large hand, an open grip on a small one
  • Hysteresis so joint jitter can’t chatter a grab
  • Two hands → one continues the drag, doesn’t drop
  • Lost tracking counts as a release, not a freeze
Assets

Every catalog entry has a model

Generated rather than downloaded, because the anchor engine depends on two things sourced models never come with: origins at the base (a centre pivot sinks furniture halfway into the floor) and real-world centimetre scale. 1,786 triangles for all twelve, no textures.

No smoke, no mirrors

What’s real, what’s simulated

The app you just launched runs in a browser — so it matters exactly which parts are the shipped Lens code and which are scaffolding standing in for hardware.

● Real shipped code

Instances of the shipped Scripts/*.ts, compiled to ES modules and wired as the Inspector would wire them. Not reimplementations.

  • VoiceCommandController — parse, execute, spawn animation, debounce, feedback
  • SurfaceAnchorEngine — probe queue, floor calibration, classify, retry, overlap, wall-adjacent, reseat
  • PBRMaterialSwapper — clone-once, cross-fade, guarded uniform writes
  • FURNITURE_CATALOG, SpatialisRegistry, the tween system
  • The 12 .glb models the Lens would load

● Simulated scaffolding

Stands in for hardware the browser doesn’t have. Replaced on device.

  • The room itself, and ray hit tests against it
    → World Query on device
  • Head pose, from the arrow keys
    → the headset’s tracking on device
  • Mouse drag and scroll as pinch and scale
    → SIK hand tracking on device. SpatialGestureController does not run here; its state machine is covered by tests. Release does call the real reseat().
  • Web Speech API
    → the ASR module on device
  • three.js rendering
    → the Spectacles display on device

The real thing

Two front doors, one codebase

The app you can launch above is the browser simulator — it hosts the shipped subsystems against a simulated room so anyone can try Spatialis without hardware. The Lens is the same four Scripts/*.ts files running inside Lens Studio for Spectacles. npm run sync:lens keeps the Lens project’s copy identical to the source; nothing is forked.

● Browser simulator

For judges, for the video, for anyone without a headset.

  • Real parser, anchor engine, material swapper — hosted in a page
  • Room, hit tests, head pose and pinch are simulated
  • Launch app

● Lens Studio project

LensProject/ — SPECS target, scene wired by script, runs in the editor’s Preview.

  • Open LensProject/LensProject.esproj in Lens Studio 5.22+, sign in to My Lenses, press ▶ in Preview
  • Say “give me a navy velvet sofa” — the runtime log shows the spawn, and the sofa appears
  • No room surfaces in the desktop Preview, so pieces float; on Spectacles, World Query anchors them
Run it yourself

Node is the only dependency

No Lens Studio, no headset, no account.

# clone and verify
$ git clone https://github.com/mrnetwork0001/Spatialis.git && cd Spatialis
$ npm install
$ npm run typecheck   # strict type check of all four subsystems
$ npm test            # 74 behavioural tests

# launch this page and the app
$ npm run sim         # builds the bundle, serves on :8777
